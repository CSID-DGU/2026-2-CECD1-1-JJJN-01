# SMPL+H 자유투 프로젝트

SMPL+H 체형 하나와 기준 자유투 동작 하나를 이용해, 전신 균형과 팔로스루를 유지하면서 제한된 보정으로 득점을 개선하는 프로젝트입니다.

현재 기준은 `runs/spl_overhand_v3`와 430에피소드 체크포인트 `runs/residual_ppo_overhand/checkpoints/interrupted_000037842_1791695181`입니다. 표시를 넣어 투영 좌표를 확인한 결과 오른손 슈팅 손은 화면 왼쪽/가운데에 있고 그 엄지도 손바닥 정면 기준 화면 왼쪽에 있습니다. 화면 오른쪽 손은 왼손 가이드 손입니다. 학습은 중단 상태이며 430회부터 재개할 수 있습니다.

## 릴리스 주변 손 움직임 보정 결과

최신 결과는 `runs/spl_release/review.html`입니다. 물리 영상, 보정 전후 비교, 손목·공 속도, 팔로스루 검증 결과를 함께 볼 수 있습니다.

```powershell
.\.venv\Scripts\python.exe src/calibrate_release.py --render
```

또는 `.\.venv\Scripts\python.exe src/run_spl_pipeline.py --stage calibrate`로 실행합니다. 렌더링만 갱신하려면 `.\.venv\Scripts\python.exe src/render_shooting.py --output runs/spl_release`를 사용합니다. SPL 원본과 기존 리타기팅 기준, 이전 `runs/spl_shooting` 결과는 유지합니다.

원본 공의 자유 비행을 중력 9.81m/s²로 피팅하고 손과의 분리를 확인해 릴리스 전환 프레임을 144에서 149로 다시 추정했습니다. 이는 접촉 정답 표식이 아니라 수 프레임의 불확실성이 있는 추정입니다. 피팅 구간별 공 속력은 약 6.31–6.63m/s입니다. 원본 손목 속력은 약 1.21m/s이며, 현재 체형의 팔 길이와 뼈 방향을 반영한 손목 기준 속력은 약 0.55m/s입니다. **공 속도와 손목 속도를 같은 목표로 취급하지 않습니다.**

손목 위치는 기존 체형으로 변환한 원본 궤적을 릴리스 위치에서 정렬합니다. 손바닥 방향은 손목과 검지·중지·소지 MCP 표식에서 강체 방향을 추정하고 보정 시작 자세에 정렬합니다. 손가락 관절 자세·접촉력의 복원은 아닙니다. 보정은 동작 시간 0.683–1.533초에만 적용하고, 어깨 각 축 ±0.15rad, 팔꿈치 ±0.20rad, 손목 각 축 ±0.65/0.65/0.45rad 이내로 제한했습니다. 몸통·다리·왼팔 기준은 추가로 변경하지 않습니다. 보정 시작·종료에서 위치·속도·가속도가 이어지도록 연결하고, 마지막에는 원래 팔로스루 자세를 유지합니다. 전신은 기존 토크 제한과 접촉을 사용하는 QP 제어로 움직입니다.

| --- | --- | --- |

손목 RMS는 **각 실행에서 사용하는 기준 동작에 대한 추종 오차**입니다. 보정 후 릴리스 손목 속도 오차는 보정 기준 대비 0.140m/s, 체형 변환 원본 대비 0.274m/s입니다. 마지막 자세 유지 구간의 손목 RMS는 오른쪽 0.038cm, 왼쪽 1.77cm입니다. 최대 제외 손·공 겹침은 약 3.00mm, 잡는 동안 몸통·팔과 공의 접촉 침투는 0mm, 최대 잡기 반력은 약 65.7N입니다. 외부 보조 힘, 릴리스 시 속도 변경, QP 대체 제어 및 수치 경고는 모두 0입니다.

이 결과는 **손 움직임·균형·팔로스루 추종 단계의 검증**입니다. 공 속도가 개선된 결과는 아닙니다. 공 속도를 팔의 목표로 직접 주었던 빠른 시험은 자세 왜곡·보조 손 겹침·접촉 반력 등의 문제로 채택하지 않았습니다. 고정 잡기 제약은 공이 손 안에서 움직이거나 손가락 끝을 거쳐 분리되는 운동을 표현하지 않습니다. 다음 물리 구현 과제는 손·공의 상대 이동과 분리 시점을 표현하는 잡기 모델입니다. 원본 공 속도와 방향을 재현하는지 검증한 후 제한된 보정으로 득점을 학습하는 것이 현재 목표에 맞습니다.

주요 추가 출력은 `release_comparison.png`(보정 전후 궤적·속도 비교), `source_release_analysis.json/.npz`(원본 피팅과 손바닥 방향), `release_diagnostics.json/.npz`(균형·팔로스루 기준 및 실제 손목/잡기 지점 속도)입니다. `shooting_report.json`에 관절 보정 범위, 원본 해시, 실행 파라미터와 검증 결과도 기록합니다. 자세·접촉·발 이동 등의 통과 기준은 이 프로젝트의 공학적 기준이며 인체 생체역학 검증을 의미하지 않습니다.

## 공을 포함한 자유투 결과

`runs/spl_shooting/review.html`을 브라우저에서 열면 영상, 궤적, 측정 결과를 볼 수 있습니다.

```powershell
.\.venv\Scripts\python.exe src/shoot_spl.py --render
```

또는 `.\.venv\Scripts\python.exe src/run_spl_pipeline.py --stage shoot`로 같은 작업을 실행합니다. 렌더링만 다시 만들려면 `src/render_shooting.py`를 실행합니다. 별도 패키지 추가 설치 없이 현재 `.venv`를 사용합니다.

기준은 SPL P0002 / T0065의 81–183 프레임, 릴리스 추정 프레임 144입니다. 0.7초 준비, 원래 속도의 1.7초 동작, 2초 마지막 자세 유지로 총 4.4초 실행합니다. 몸통·다리 기준은 유지하고 양팔은 손바닥 방향과 공·팔 간격을 보정합니다. 상완 각도 보정 범위는 오른쪽 축별 ±0.35rad, 왼쪽 ±0.55rad이며 손목은 모델 관절 범위 안에서 피팅합니다. 이 보정은 학습 결과가 아닙니다.

공은 반지름 0.12m, 질량 0.62kg의 자유 강체입니다. 준비·슛 동안 오른손과 공 사이의 해제 가능한 weld 제약으로 잡기를 근사합니다. 제어기에는 붙잡은 공의 질량과 관성을 포함합니다. 릴리스에서는 제약만 끄며 **공의 위치·속도 변경, 발사 충격량, 골반 보조 힘을 넣지 않습니다.** 이후에는 중력과 실제 충돌로 움직입니다. 림 중심은 `(4.225, 0, 3.05)m`, 림 안쪽 반지름은 0.225m입니다. 이 배치와 충돌 계수는 초기 실험 설정입니다.

현재 기준 실행은 **넘어짐 없이 완료되지만 득점에는 실패합니다.** 릴리스 속력 약 1.16m/s, 최고 높이 약 2.06m로 림 높이 3.05m에 미치지 못합니다. 원본 SPL의 `made` 기록과 현재 체형의 물리 실행 결과는 구분해야 합니다. 손목 추종 RMS는 왼쪽 약 3.12cm, 오른쪽 약 3.51cm입니다. 이는 공을 위해 보정한 기준 동작에 대한 오차입니다. 발목 최대 수평 이동 약 4.50mm, 공 잡기 제약의 최대 위치 오차 약 0.20mm, 최대 잡기 반력 약 22.3N입니다. 정확한 수치는 매 실행의 `shooting_report.json`에서 확인합니다.

잡기는 **손가락 접촉·마찰에 의한 실제 파지가 아닙니다.** 양손과 공의 충돌은 제외하며 왼손은 보조 자세만 추종합니다. 제외된 손 형상과 공의 겹침도 별도로 측정합니다. 기존 합성 손가락 자세와 발을 바닥에 유지하는 기준을 사용합니다. 공·바닥·림·백보드 충돌 계수는 실측 보정하지 않았고 공기저항·마그누스 효과는 없습니다. 이 결과를 정밀 손 조작이나 현실 자유투의 검증으로 해석하면 안 됩니다.

| 출력 (`runs/spl_shooting/`) | 내용 |
| --- | --- |
| `review.html` | 영상, 시간 슬라이더로 보는 궤적, 결과 링크 |
| `shooting.mp4`, `shooting.gif` | 전체 환경과 전신을 함께 보여주는 물리 실행 |
| `storyboard.png`, `release.png` | 준비·슛·릴리스·팔로스루 장면 |
| `trajectory.png` | 측면·평면 궤적, 공 속도, 추종 오차 |
| `ball_trajectory.csv` | 매 물리 스텝의 시간·공 위치·선속도 |
| `shooting.npz` | 전신 및 공 상태, 추종 오차, 잡기 활성 상태 |
| `holding_reference.npz` | 공을 위해 양팔을 보정한 별도 기준 동작 |
| `scene.xml`, `shooting_report.json` | 실행 모델, 원본 해시, 파라미터·측정·한계 |

`--output <경로>`로 별도 결과 폴더를 지정할 수 있습니다. 같은 출력 폴더로 재실행하면 결과를 갱신합니다. 원래 `free_throw_reference.npz`와 SPL 원본은 수정하지 않습니다. `--release-offset 0.02`는 동작 속도나 공 속도를 바꾸지 않고 제약 해제만 20ms 늦춥니다. 이 옵션의 다른 값은 별도 안정성 검증이 필요합니다.

## 후보 선택과 공 없는 추종

`runs/spl_tracking/review.html`에서 원본 후보를 재생하고 시작·릴리스·종료 프레임을 지정할 수 있습니다. 저장한 JSON을 `runs/spl_tracking/selection.json`에 배치한 뒤 아래 명령으로 리타기팅·추종·영상을 갱신합니다.

```powershell
.\.venv\Scripts\python.exe src/run_spl_pipeline.py --stage all
```

이 명령의 `all`은 기존 공 없는 파이프라인입니다. 새 기준으로 공 포함 결과도 갱신하려면 이어서 `--stage shoot`를 실행합니다. 원본 모델이 바뀌면 해시 검사가 이전 리타기팅 파일의 재사용을 거부합니다.

SPL 데이터 출처: [SPL Open Data 자유투](https://github.com/Sport-Performance-Lab/SPL-Open-Data/tree/main/basketball/freethrow). 원본 데이터의 CC BY-NC-SA 4.0 조건을 따릅니다. 새 환경에서 필요한 추종·렌더링 추가 의존성은 `requirements-spl.txt`에 있습니다.

## 바로 확인하기

프로젝트 루트의 PowerShell에서 실행합니다. `.venv`의 Python을 직접 사용하므로 별도 활성화가 필요 없습니다.

정지 상태로 전신 모델을 회전·확대해서 살펴보기:

```powershell
.\.venv\Scripts\python.exe src/preview_humanoid.py
```

물리 시뮬레이션 실행:

```powershell
.\.venv\Scripts\python.exe src/preview_humanoid.py --simulate
```

기본 미리보기는 물리 스텝을 진행하지 않습니다. `--simulate`에서는 중력과 접촉을 계산하고 PD 제어기가 초기 관절 목표를 유지합니다. **이 기본 뷰어에는 추종용 균형 제어기가 연결되지 않아 넘어집니다.** 전신 균형과 슛은 상단의 SPL 실행 명령으로 확인합니다. 창을 닫으면 종료합니다. `--pose t_pose`로 기본 T 자세를 볼 수 있습니다.

화면 없이 물리 검증 및 MuJoCo 렌더링 저장:

```powershell
.\.venv\Scripts\python.exe src/check_humanoid.py --render
```

결과는 `runs/humanoid_check/report.json`, 이미지는 `runs/humanoid_check/preview.png`에 저장합니다. 같은 출력 경로로 다시 실행하면 결과를 갱신합니다.

## 물리 모델 구성

| 항목 | 현재 구성 |
| --- | --- |
| 원본 | `data/models/smplh/SMPLH_MALE.pkl`, 체형 계수 10개 모두 0 |
| 좌표계 | X 전방, Y 왼쪽, Z 위쪽. SMPL `(x,y,z)`를 `(z,x,y)`로 변환 |
| 골격 | 원본 SMPL+H의 52개 관절 위치와 부모 관계 유지 |
| 골반 | 구동기 없는 free joint, 월드 고정·보조 지지대·중력 보상 없음 |
| 제어 | 제한된 회전축 93개, 각 축에 토크 제한이 있는 PD 위치 구동기 |
| 전체 자유도 | `nv=99` (골반 6 + 제어 축 93), `nq=100` |
| 몸통·팔다리 | 타원체 및 캡슐 강체 |
| 발 | 뒤꿈치/발바닥과 앞발의 상자 형상, 발끝 관절 및 발바닥 접촉 센서 |
| 손 | 양손 손바닥 상자와 손가락 30개 마디의 캡슐, 손바닥·손끝 site |
| 질량 | 기본 75kg, 부위별 가정 비율로 배분, 형상으로 관성 계산 |
| 시뮬레이션 | 1ms, implicitfast, 중력 9.81m/s² |
| 센서 | 골반 각속도·가속도, 양발 발바닥 touch |

`standing`은 팔을 내린 **초기 자세의 이름**입니다. 기본 자세의 발 충돌 형상은 바닥 위 약 5mm에 놓이며, 시뮬레이션에서 중력에 의해 지면과 접촉합니다.

팔다리 굵기, 발·머리 크기는 원본 기본 메시에서 추정하고 몸통·손바닥은 단순화했습니다. SMPL의 포즈 보정과 피부 변형을 렌더링하는 모델은 아닙니다. 현재 이미지에 보이는 것은 실제 물리 충돌 형상입니다.

질량 분포·관절 한계·토크 한계·PD 게인·마찰은 **실측 인체 값이 아닌 초기 공학적 설정**입니다. 체중을 변경해도 근력·게인이 자동 보정되지는 않습니다. 특히 엄지 축과 손 자세는 향후 공을 잡는 기준 동작에 맞춰 보정해야 합니다.

관절 근처의 겹침을 피하기 위해 골격 트리 거리가 2 이하인 부위 사이와 같은 손 내부의 충돌을 제외했습니다. 그 외 몸의 자체 충돌, 반대 손과의 충돌, 손과 외부 물체의 충돌은 활성화했습니다. 이 제외 범위는 의도적인 단순화이며 향후 접촉 과제에 맞춰 조정할 수 있습니다.

## 모델 재생성

```powershell
.\.venv\Scripts\python.exe src/build_humanoid.py
```

`--mass 75`, `--model <원본 pkl 경로>`, `--output <출력 xml 경로>`를 지원합니다. 생성되는 파일:

- `assets/smplh_humanoid.xml`: 외부 자산 없이 로딩할 수 있는 MJCF.
- `assets/smplh_humanoid.json`: 원본 해시, 체형, 좌표 변환, SMPL 관절과 MuJoCo 축 매핑, 구동기 설정 및 가정.

재생성은 지정한 XML 및 JSON을 갱신합니다. 원본 PKL은 수정하지 않습니다.

한글 Windows 경로에서 MuJoCo의 네이티브 파일 로딩이 실패하는 문제를 피하기 위해 `humanoid_model.load_model()`은 Python으로 XML을 읽어 `MjModel.from_xml_string()`에 전달합니다. 이 로더는 현재처럼 외부 include/mesh 파일이 없는 MJCF용입니다.

## 잔차 학습을 위한 접촉 모델 준비

## 잔차 PPO 학습과 재개

`src/free_throw_env.py`는 20Hz 정책, 200Hz 전신 제어, 1ms 물리 계산으로 실행합니다. 정책은 슛 주변의 팔꿈치·손목·전완·손가락 보정과 한 번 결정하는 준비 weld 해제 시점을 출력합니다. 보정은 매끄럽게 필터링하고 몸통·다리 기준은 유지합니다. 보상은 실제 릴리스 상태에서 계산한 목표 발사 궤적 오차, 실제 비행 중 골대 거리, 물리 조건을 통과한 실제 득점, 자세·균형·보정 크기 및 변화량으로 구성합니다. 공의 속도나 외부 힘을 설정하는 정책 행동은 없습니다.

처음부터 새 학습을 실행할 때(현재 실행과 별도의 폴더):

```powershell
.\.venv\Scripts\python.exe src/train_residual.py --output runs/new_residual_ppo --episodes 10000 --workers 2
```

현재 선택한 학습 실행은 `runs/residual_ppo_overhand/`이며 430에피소드에서 중단되어 있습니다. `progress.json`에서 에피소드·정책 스텝·상태를, `episodes.jsonl`에서 각 슛의 물리 조건과 궤적을 확인합니다. `stdout.log`와 `stderr.log`는 백그라운드 실행 로그입니다. 최대 예산은 누적 10,000에피소드입니다. 500에피소드 또는 5분마다, 성능이 개선되면 추가로 체크포인트를 저장합니다. 첫 본 평가 500회, 이후 1,000회 간격으로 고정된 초기 상태에서 탐색 잡음을 끈 정책을 평가합니다. 초기 상태가 고정되어 있으므로 반복 평가 횟수로 일반화 성능을 주장하지 않습니다. `src/watch_residual.py`는 최고 체크포인트가 갱신되면 평가 영상을 생성하며, 최신 영상 경로는 `best_evaluation.json`에 기록합니다.

평가 정책이 물리 조건을 계속 위반하거나 2,000회까지 기준 대비 발사 개선이 없으면 중단합니다. 최고 평가 성능이 2,000회 동안 개선되지 않아도 중단합니다. 최대 예산은 성공 보장이 아니며 조기 중단 원인은 `progress.json`의 `stop_reason`에 기록합니다.

재개할 체크포인트는 `latest.json`에, 최고 성능은 `best.json`에 기록합니다. 예:

```powershell
$taskCheckpoint = Join-Path (Resolve-Path runs/residual_ppo_overhand).Path ((Get-Content runs/residual_ppo_overhand/latest.json -Raw).Trim() | ConvertFrom-Json).checkpoint
.\.venv\Scripts\python.exe src/train_residual.py --resume $taskCheckpoint --output runs/residual_ppo_resumed --episodes 10000 --workers 2
```

현재 학습을 정상 중단하고 마지막 상태를 저장하려면 `runs/residual_ppo_overhand/STOP` 파일을 만듭니다. 현재 PPO 업데이트가 끝난 뒤 저장하고 종료합니다. 종료를 확인한 후 새 출력 폴더에서 재개합니다. 동일한 학습에 두 프로세스를 동시에 연결하지 않도록 `training.lock`을 사용합니다.

체크포인트 폴더 하나에는 정책·가치망·옵티마이저(`policy.zip`), 관측 정규화(`normalization.pkl`), 난수 상태(`rng.pt`), 누적 학습 정보, 전체 패키지 버전, 실행 코드, 고정된 기준 동작과 물리 장면이 들어 있습니다. `COMPLETE.json`이 있어야 저장 완료로 인정하며 `manifest.json`으로 파일 무결성을 검사합니다. Windows 폴더 이름 변경 문제를 피하기 위해 파일 저장과 완료 표시를 끝낸 후에만 `latest.json`을 갱신합니다.

다른 컴퓨터에는 해당 체크포인트 폴더 전체를 복사하고 같은 Python·패키지 버전을 준비합니다. 체크포인트 폴더에서 아래처럼 실행할 수 있습니다. PPO 재개에는 원본 `SMPLH_MALE.pkl`이나 전체 SPL 데이터셋이 필요하지 않습니다. 새 체형 생성이나 리타기팅에는 원본 자료가 필요합니다.

```powershell
python src/train_residual.py --resume . --output resumed_training --episodes 10000 --workers 2
```

재개는 **새 에피소드부터** 진행하며, 중단 순간의 물리 상태·QP 내부 상태·미완료 rollout을 이어 붙이지 않습니다. 정책·옵티마이저·정규화 통계·누적 카운터는 유지하지만, 다른 컴퓨터에서 이후 결과가 비트 단위로 동일하다고 보장하지 않습니다. 정규화된 관측을 사용하는 정책이므로 `policy.zip`만 복사해서는 동일하게 실행되지 않습니다.

온라인 환경의 0 보정이 기존 발사 결과를 재현하는 테스트, 실제 체크포인트에서 옵티마이저·정규화 복원과 추가 학습을 확인하는 테스트를 `tests/test_rl_env.py`, `tests/test_rl_checkpoint.py`에 추가했습니다. 처음 8에피소드 시험 후 10회까지 재개했고, 체크포인트 안의 코드만 실행해 12회까지 추가 학습하는 것도 확인했습니다. 초기 최고 평가 영상은 `runs/residual_smoke_v2/best_evaluation/review.html`에 있습니다. 이 초기 결과에는 아직 득점이 없습니다.

## 공 위에서 시작하는 준비 자세

`src/prepare_overhand.py`가 생성한 430회 학습 기준은 `runs/spl_overhand_v3/`입니다. 초기 오른손 손바닥은 공 중심보다 약 13.3cm 위에 있고 아래를 향합니다. 손 방향을 공을 들어 올리는 .10~.86초 동안 바꾸며, 기존 .60~.88초의 늦은 방향 회전을 제거했습니다. 손과 공의 상대 위치는 weld로 유지하므로 공의 준비 궤적도 함께 바뀝니다. 보조 손의 간격과 .74~.98초의 물러나는 경로를 보정해 공과 왼손이 강하게 충돌하지 않도록 했습니다.

`runs/residual_ppo_overhand/evaluations/episode_430/handedness_check.png`에서 오른손 엄지를 빨간색, 왼손 엄지를 청록색으로 표시했습니다. 릴리스 시 오른손 엄지 밑관절은 오른손 새끼손가락보다 화면 왼쪽에 13.9mm 떨어져 있습니다. 따라서 손 골격을 뒤집지 않고 `spl_overhand_v3`와 430회 체크포인트를 그대로 사용합니다.

```powershell
.\.venv\Scripts\python.exe src/prepare_overhand.py --output runs/new_overhand_reference --render
.\.venv\Scripts\python.exe src/train_residual.py --bundle runs/new_overhand_reference --output runs/new_overhand_training --episodes 10000 --workers 2
```

현재 손 골격과 행동 축은 변경하지 않았으므로 430회 체크포인트에서 이어갈 수 있습니다. `runs/active_training.json`에 현재 상태를 기록했습니다.
